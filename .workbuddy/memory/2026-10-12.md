### 交付物

### 实测结论（关键，后续改代码必须守住）
| 场景 | 实测结果 |
|---|---|
| 干净的单对 Thought-Action | 73 → 73 字符，不截断 |
| 模型多吐两对 | 178 → 57 字符，正确截断到第一对 |
| **多行 Finish（正文含 `**` `【】` `##` `-`）** | **326 → 326，不截断**，FINISH_RE 拿满 272 字符 |
| Finish 正文含 `Thought:` 开头的行 | 被截断 → 括号失配 → kind=error（**隐患**） |
| Finish 正文含 `Observation:` 开头的行 | 同上（**隐患**） |
| Finish 正文以 `**第1天**` 开头 | 正常 kind=finish |
| `get_weather(city=北京)` 无引号 | BARE_ARG_RE 兜底成功 |
| `get_weather(city="北京", date="today")` | 进入 _execute_tool 后被 signature 过滤掉 date |
| `search_flight(...)` 工具名不存在 | _parse_action 仍返回 tool，由 _execute_tool 拒绝 |

### 核心机制解释（回答用户"为什么这样输出"）
1. **为什么多行 Finish 没被截断**：`THOUGHT_ACTION_RE` 的 lookahead 是
   `(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)`。只有当换行后紧跟这三个关键词之一
   才切断；Markdown 正文的行首是 `#`/`-`/`**`/`【`/`##`，一个都不匹配，
   所以 `.*?` 一路懒匹配到字符串末尾 `\Z`。**这是运气，不是设计**。
2. **为什么 Observation 是英文**：`attraction.py:35-36`
   `if response.get("answer"): return response["answer"]` —— 零后处理，**完全没有翻译层**。
   Tavily 的 answer 是它自己用一次 LLM 对搜索结果做的英文总结，代码只是转发。
   查询里带英文词 `Smoky haze` 会把搜索结果语料进一步推向英文。
3. **英文如何影响最终答案**：Observation 原样 `append` 进 `prompt_history`，
   下一轮作为上下文。`system_prompt` 只说了"你是一个智能旅行助手"，
   **没有一条"必须用中文回答"的硬约束**，所以模型会镜像上下文语言/中英混杂。
4. **连锁反应**：第 1 轮 `weather.py:31` 取 `weatherDesc[0]["value"]`（wttr.in 的英文字段）
   → Observation 里是 `Smoky haze` → 第 2 轮模型把这个英文串原样当 `weather=` 参数抄回去
   → 又强化了英文 query。**工具的返回措辞直接决定下一轮模型的动作**。
5. **第 4 轮为什么没跑**：`kind == "finish"` 在 `run()` 第 94-96 行直接 `return payload`，
   不 append Observation，也不再进循环。所以日志里 `已截断` 和 `Observation` 都没出现。
6. **`_parse_action` 不做校验**：`CALL_RE = ^\s*(\w+)\s*\((.*)\)\s*$` 对任何标识符都放行，
   工具名对错、参数多少全在 `_execute_tool` 才判。读代码时别把两者职责搞混。

### 建议的修复项（用户尚未确认是否动手）
1. **`_truncate` 应跳过 Finish 行**（最值得改的一处）：在截断前先判断
   `action_str.startswith("Finish")`，是 Finish 就不截断。
   现在只要答案正文出现一行以 `Thought:`/`Action:`/`Observation:` 开头就会崩。
2. `ACTION_RE.search` 取的是**第一个** `Action:`；若模型在 Thought 里引述"Action:"会取错。
   可改成 `findall` 取最后一个。
3. `FINISH_RE` 的 `.*` 贪婪会吃到最后一个 `]`；正文含 `[1]` 这类引注时会被多吞（当前无害）。
4. `attraction.py` 的 `answer` 需要语言约束（改 query 全中文，或加一句后处理）。
5. `weather.py:32` 的 `temp_C` 是**字符串**（wttr.in 返回 "23" 不是 23），
   直接 `%s` 拼接，所以日志里显示 `气温23摄氏度`。

## 追加：解释第 ③ 步「截断」（_truncate）到底在防什么

### 交付物
`_tools/why_truncate.py` — 对照实验脚本。
构造一个「一口气把活全干完」的模型（一次回复吐 3 对 Thought-Action
+ 2 条**自己伪造的 Observation**），分别在有截断 / 无截断的 Agent 里跑，
打印真实工具调用次数与最终答案。`NoTruncateAgent` 子类只覆盖 `_truncate`。

### 实测对照结果（重要教学素材）
| | 有截断 | 无截断 |
|---|---|---|
| 进历史的段数 | 6（1 对 + 2 条真 Observation） | 4（但含 3 对 + 2 条伪造 Observation） |
| **真实工具调用** | 2 次 | **0 次** |
| 最终答案 | 故宫博物院、天坛公园（真数据） | 颐和园、长城（**模型编的**） |

无截断时的失败链路（已 dump 出完整 history 验证）：
`ACTION_RE` 取第一个 `Action:` → action_str 拖着一大串尾巴（末尾是 `]`）
→ `CALL_RE` 要求整体形如 `name(...)` 且 `\s*$` 收尾 → 失配 →
返回「无法解析工具调用」错误 → **而这条错误消息把 action_str 原样拼了进去**，
于是历史里又多了 2 处伪造的 `Observation:`（实测 joined 里共 5 次）
→ 模型认为工具早跑完了 → 直接 Finish 引用幻觉数据。

### 核心机制（讲给学生听的三句话）
1. **截断截的是"轮次"，不是"答案"**：只保留第一对 Thought-Action，多余的全丢。
2. **根因在 `_call_llm()` 的 `"\n".join(prompt_history)`**：历史被压平成一个
   格式高度规则的长字符串，模型最自然的续写就是**继续按这个模式往下写**
   （in-context pattern completion），顺手把 Observation 也补上。
   `system_prompt` 第 18 行"每次只输出一对"只是软约束，必须在代码侧硬拦。
3. **最大危害是幻觉数据进了"事实层"**：`Observation:` 前缀在协议里代表
   "真实工具返回"，模型一旦伪造成功，Agent 就从"基于工具结果推理"
   退化成"基于自己的想象推理"，而且输出格式漂亮、语气肯定，**表面看不出来**。

### 补充澄清
`_truncate()` 每轮都被调用（agent.py:87），但它只在
`truncated != llm_output.strip()` 时才打印「已截断」日志。
所以**大多数轮次它什么也不做**（用户那三次运行 73→73、326→326 都没触发），
它是一道常设安检，不是每轮都发生的事件。

### 正则要点
`(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)` 是**前瞻**（不消耗字符）：
停下来当且仅当"换行后紧跟三个关键词之一"或"已到字符串末尾"。
配合 `re.DOTALL`（让 `.` 匹配换行）与 `.*?` 懒匹配，实现"切到下一个轮次的开头"。
副作用见上一节第 1 条（Finish 正文含 `Thought:` 开头的行会被误伤）。

## 追加：修复 `agent.py` 的截断与 ACTION_RE 两处隐患（已落地）

### 改了什么（`work/demo1/agent.py`）

**1. 新增 `_is_finish()` + `_truncate()` 遇到 Finish 整段放过**
```python
@staticmethod
def _is_finish(llm_output: str) -> bool:
    m = ACTION_RE.search(llm_output)
    return bool(m) and m.group(1).strip().startswith("Finish")
```
`_truncate()` 第一行就是 `if self._is_finish(llm_output): return llm_output.strip()`，
并在"本来会被切掉"时打印 `检测到 Finish：跳过截断（否则答案会被腰斩）`。
`_is_finish` 与 `_parse_action` 用**完全相同**的取法，保证两处判断不打架。

**2. `ACTION_RE` 改为只认行首**
```python
ACTION_RE = re.compile(r"(?:^|\n)[ \t]*Action:[ \t]*(.*)", re.DOTALL)
```
老写法 `re.search(r"Action:\s*(.*)")` 会抓到 Thought 里**引述**的 "Action:"。

**3. `THOUGHT_ACTION_RE` 的 Action: 也要求行首（关键，容易漏）**
```python
THOUGHT_ACTION_RE = re.compile(
    r"(Thought:.*?(?:^|\n)[ \t]*Action:[ \t]*.*?)"
    r"(?=\n\s*(?:Thought:|Action:|Observation:)|\Z)", re.DOTALL)
```
只改 ACTION_RE 不够：旧 `THOUGHT_ACTION_RE` 仍会在引述处就切断，
把真正的 Action 整条丢掉，解析照样失败。两处必须同时加行首约束。

**重要结论：Action 要取「第一处行首」，不能取最后一处。**
因为 Finish 正文里可能有一行以 `Action:` 开头（列举步骤），
取最后一处会把真正的 `Finish[...]` 丢掉。（此前我一度建议改 findall 取最后一个，是错的。）

### 回归测试（`_tools/verify_loop.py` 已重写为带期望值的回归测试）
内置复刻「修复前旧逻辑」，同屏输出 修复前 kind → 修复后 kind 对照。
**结果：12 / 12 通过**，其中 4 条行为发生变化：

| 用例 | 修复前 | 修复后 |
|---|---|---|
| ⑥ Finish 正文含 `Thought:` 开头行 | error | **finish** |
| ⑦ Finish 正文含 `Observation:` 开头行 | error | **finish** |
| ⑧ Finish 正文含 `Action:` 开头行 | error | **finish** |
| ⑨ Thought 里句中引述 `Action:` | error | **tool get_weather** |

其余 8 条（干净一对、多吐截断、两参数、多行 Finish、无 Thought、全无 Action、
Finish 不闭合、工具名不存在）行为不变，说明没改坏。

### 其他验证

## 追加实验：给 system_prompt 加「语言要求」，验证语言传染链

### 改动
`work/demo1/system_prompt` 新增「# 语言要求（务必遵守）」三条（441 → 731 字符）：
1. Thought 和最终答案必须全部使用简体中文
2. Observation 可能是英文原文，**绝不可照抄进最终答案**，要理解后用中文表达
3. 调用工具时参数值也尽量用中文（例如 weather 写"烟霾"而不是 "Smoky haze"）

原文件已备份到 `_runs/system_prompt.原始版`。

### 实测对照（同一命令，同为 3 轮结束）
| 指标 | 对照组（原提示词） | 实验组（加中文约束） |
|---|---|---|
| system_prompt 长度 | 441 | 731 |
| **工具参数** | `weather='Smoky haze'` | **`weather='烟霾'`** ← 模型自己翻的 |
| 第 2 轮 Thought | "烟霾（Smoky haze），气温23摄氏度" 保留了英文原名 | "烟霾，气温23摄氏度" 英文被丢掉 |
| Tavily 返回 | 552 字符纯英文，无中文 | 496 字符，夹中文景点名 `(紫禁城)(万里长城)(天坛)(颐和园)` |
| 最终答案 | 491 字符，北海公园/颐和园线 | 387 字符，古北水镇/紫禁城/长城线 |
| 最终答案英文字母数 | 1（N95 的 N） | 0 |

### ★ 三条核心结论（教学价值最高）
1. **提示词能改「模型写什么」**：`weather="Smoky haze"` → `weather="烟霾"` 是**模型自己翻译**的，
   不是代码做的。语言约束成功下渗到了「工具参数」这一层。
2. **提示词改不了「工具返回什么」**：Observation 仍是英文，因为它不是模型生成的。
   `agent.py` 里是 `observation = self._execute_tool(...)` 然后
   `prompt_history.append("Observation: %s" % observation)` —— 代码硬拼进去的字符串。
   `attraction.py:36 return response["answer"]` 拿到什么就是什么。
3. **但提示词能改变模型「如何看待」英文 Observation**：同一段英文，对照组把它抄进
   Thought 和答案，实验组只在内部消化，输出零英文（连 `Gubei Water Town` 这类括号注释都省了）。
4. **意外收获**：query 从英文变中文后，检索命中语料变了 → 推荐景点完全不同
   （古北水镇 vs 北海公园）。**参数语言显著影响检索质量与内容**，对 RAG/工具类 Agent 很实际。
